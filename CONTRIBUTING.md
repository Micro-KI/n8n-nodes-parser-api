# Contributing

Thanks for helping. Bug reports and pull requests are welcome.

1. Open an issue first for larger changes, so we can agree on the approach.
2. Read the [rules for changes](docs/development.md#rules-for-changes). Stable names and no runtime dependencies matter most.
3. Run `npm run lint` and `npm test` before you push. CI runs both on every pull request.
4. Describe the change in `CHANGELOG.md` under a new version heading.

Never commit an API key other than the public test key `pak_test_X0001`.
